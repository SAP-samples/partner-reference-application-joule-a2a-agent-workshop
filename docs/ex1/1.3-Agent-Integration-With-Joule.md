# Agent Integration with Joule

In this exercise, you wire the deployed A2A agent into Joule and verify the complete integration end to end. This involves configuring SAP BTP destinations, deploying Joule capabilities using the CLI, and testing the agent through the Joule conversational UI.

## Prerequisites

Before starting this exercise, ensure you have:

- [Deployed the agent and Joule capabilities.](./1.2-Deploy-Agent-And-Joule-Capabilities.md)

### Create Site in SAP Build Work Zone and Enable Joule

#### Create a Site

1. Go to **BTP Cockpit → HOW-PA Joule Agent nnn → Services → Instances and Subscriptions**.
2. Select the **SAP Build Work Zone, standard edition** subscription to open the **SAP Build Work Zone**.
3. Choose **Create Site**.
4. Enter a site name, for example, *Partner Reference Application*.
5. Choose **Create**.

> [!TIP]
> **Reference:** [Create a Site](https://help.sap.com/docs/build-work-zone-standard-edition/sap-build-work-zone-standard-edition/create-site)

#### Enable Joule in the Site

1. In **Site Directory**, open the site you just created.
2. Choose **Settings** (gear icon) for the site.
3. Navigate to the **Services** tab.
4. Click on **Edit** .
5. Find **Joule** in the list of services.
6. Toggle **Joule** to **Enabled**.
7. Choose **Save**.

### Access and Use Joule

1. In **Site Directory**, choose **Open Site** (external link icon) for your site.
2. The site opens in a new tab.
3. Choose the **Joule** icon in the shell bar to open the assistant.
4. Start interacting with Joule.

> [!TIP]
> **Reference:** [Joule User Guide](https://help.sap.com/docs/joule)

## Understanding the Joule Capability Integration

The capability files were generated using the [Joule A2A Agent Toolkit](https://github.com/SAP-samples/joule-a2a-agent-toolkit) plugin as part of the [Develop Coded Agent and Joule Capabilities](./1.1-Develop-Agent-And-Joule-Capabilities.md) exercise. These files define how Joule discovers, invokes, and communicates with your A2A agent.

### File Structure Overview

```
joule-capability/
├── da.sapdas.yaml              # Digital Assistant entry point
├── capability.sapdas.yaml      # Main capability definition
├── capability_context.yaml     # Context variable definitions
├── functions/
│   └── call_agent.yaml         # Function to invoke the agent
└── scenarios/
    └── invoke_agent.yaml       # Intent-to-function mapping
```

### File Descriptions

| File | Purpose | Key Contents |
|------|---------|--------------|
| **da.sapdas.yaml** | Entry point for `joule deploy` command. Defines the Digital Assistant and references the capability folder. | Schema version, capability name (`psm_joule_agent_a2a`), and local folder reference |
| **capability.sapdas.yaml** | Main capability definition that registers the agent with Joule. Contains metadata and the critical destination reference. | Namespace (`joule.ext`), display name, description, and `system_aliases` mapping to the SAP BTP destination |
| **capability_context.yaml** | Defines context variables that persist across conversation turns, enabling multi-turn conversations with the agent. | Variables: `contextId` (conversation session), `taskId` (current task tracking) |
| **functions/call_agent.yaml** | Defines the function that executes the A2A protocol call to your agent. Handles request/response flow. | Status update message, agent-request action with system_alias, response parsing, variable extraction, and result_variable linking agent output to Joule Webclient response formatting. |
| **scenarios/invoke_agent.yaml** | Maps user intents to the `call_agent` function. The description is critical. Joule uses it to determine when to invoke this capability. | Natural language description with examples, target function binding, and context variable passing |

### Key Configuration Details

**capability.sapdas.yaml** - Destination Binding:

```yaml
system_aliases:
  PsmJouleAgent:
    destination: PSM_JOULE_AGENT_A2A   # Must match BTP destination name exactly
```

**scenarios/invoke_agent.yaml** - Intent Matching:

```yaml
description: >
  Invoke this agent for any question about poetry slam events...
  Examples: "Show me all upcoming poetry slams", "Which poetry slams are fully booked?"...
```

> [!IMPORTANT]
> The `description` in `invoke_agent.yaml` determines when Joule routes user queries to your agent. Include specific examples and keywords that users might say.

## Create Destination (If Not Automatically Created by the Plugin)

This destination tells Joule where to find the agent. You need the agent's public URL to configure the destination. Get it from CF:

```bash
cf apps
```

Copy the URL for `psm-joule-agent-srv`, e.g.:
```
<your-org>-<your-space>-psm-joule-agent-srv.cfapps.<region>.hana.ondemand.com
```

1. Log in to **SAP BTP cockpit** and navigate to the **HOW-PA Joule Agent nnn Subaccount**.
2. Go to **Connectivity → Destinations**.
3. Choose **New Destination**.
4. Fill in the following:

    | Property       | Value                                  |
    |----------------|----------------------------------------|
    | Name           | `PSM_JOULE_AGENT_A2A`                    |
    | Type           | HTTP                                   |
    | URL            | psm-joule-agent-srv URL you've copied earlier |
    | Proxy Type     | Internet                               |
    | Authentication | NoAuthentication                       |

5. Under **Additional Properties**, add:

    | Property                   | Value  |
    |----------------------------|--------|
    | `HTML5.DynamicDestination` | `true` |
    | `WebIDEEnabled`            | `true` |

6. Choose **Save**.
7. On the destination tile, choose **Check Connection** (the link icon next to the destination name in **BTP Cockpit → HOW-PA Joule Agent nnn → Connectivity → Destinations**). Expect HTTP 200 or 404 (404 on `/` is expected — the agent serves on specific paths such as `/.well-known/agent.json`, not `/`).

## Update the Joule Digital Assistant

List all the deployed Joule capabilities.

```bash
# List all capabilities
joule list
```

You should already see the `psm_joule_agent_a2a` capability deployed by [Joule A2A Agent Toolkit](https://github.com/SAP-samples/joule-a2a-agent-toolkit) in the [previous exercise](./1.2-Deploy-Agent-And-Joule-Capabilities.md). If the capability is not listed, run the below command to deploy.

```bash
cd psm-joule-agent/joule-capability

# Deploy
joule deploy ./da.sapdas.yaml --compile -n "psm_joule_agent_a2a"
```

Update the capability in `sap_digital_assistant`. This pushes the capability definition directly to the Joule digital assistant and can resolve cases where `joule deploy` completed but the capability is not yet visible or active in the Joule UI.

```bash
joule update "sap_digital_assistant" --capability-file capability.sapdas.yaml
```

## Test and Troubleshoot the Joule Integration

1. Log in to **SAP BTP cockpit** and navigate to the **HOW-PA Joule Agent nnn Subaccount**.
2. Go to **Services-> Instances and Subscriptions** and open **SAP Build Work Zone**.
3. Go to the site configured and open the **Joule** panel. (Joule icon in the top right)
4. Type the following test queries one by one:

    - Prompt: `List all poetry slams`

        Expected: Joule invokes the agent and returns a formatted list of all poetry slams.

    - Prompt: `Show me only published poetry slams`

        Expected: Lists only poetry slams with status "Published".

    - Prompt: `Show details of poetry slam number 3`

        Expected: Full details including visitors and booking status.

> [!IMPORTANT]
> **Known issue — Joule routes to the wrong agent:** If Joule responds with a different agent's answer (or an unexpected response), there may be a duplicate capability with a similar description still active in your Joule instance. To resolve:
> 1. Run `joule list` to see all deployed capabilities.
> 2. Identify the old or duplicate capability (any entry that is not `psm_joule_agent_a2a`).
> 3. Delete it: `joule delete <old-capability-name>` and `joule remove sap_digital_assistant --capability joule.ext:<old-name>`.
> 4. Retry your test query in Joule.

### Troubleshooting with Claude Code

If Joule doesn't behave as expected, describe the problem to Claude Code and let it fix the code. Common symptoms are listed below:

| Symptom | Prompt to give to Claude Code |
|---------|---------------------------|
| Joule routes to wrong agent | There might be duplicate capabilities with similar descriptions. List capabilities with 'joule list' and delete the old one with 'joule delete <name>'. |
| Joule shows no response / empty answer | Destination name mismatch. Check that system_aliases.PsmJouleAgent.destination in capability.sapdas.yaml matches the exact SAP BTP destination name (case-sensitive). |
| Capability not visible after deploy | Use 'joule update sap_digital_assistant --capability-file capability.sapdas.yaml' to push the capability directly to the Joule digital assistant. |
| `Task not found` on follow-up messages | The agent fails on second turn. Strip taskId from message/send requests while keeping contextId for conversation continuity. |

#### Joule CLI Quick Reference

The complete list of Joule CLI commands is available [here](https://help.sap.com/docs/joule/joule-development-guide-ba88d1ec6a1b442098863d577c19b0c0/joule-studio-cli-commands). Below is a curated list of the most commonly used commands for your convenience.

```bash
# List all deployed capabilities
joule list

# Deploy or redeploy
joule deploy ./da.sapdas.yaml --compile -n "psm_joule_agent_a2a"

# Update capability on sap_digital_assistant directly
joule update "sap_digital_assistant" --capability-file capability.sapdas.yaml

# Deploy in two steps (compile first, then deploy)
joule compile ./
joule deploy ./da.sapdas.yaml -n "psm_joule_agent_a2a"

# Delete a capability
joule delete psm_joule_agent_a2a
joule remove sap_digital_assistant --capability joule.ext:psm_joule_agent_a2a

# Local testing without CF deployment
joule launch ./da.sapdas.yaml --compile
```
