# Deploy Pro Code Agent and Joule Capabilities

In this exercise, you build the MTA archive, deploy the agent to SAP BTP, Cloud Foundry environment Joule capabilities and verify it is working correctly using curl commands against the deployed agent.

## Prerequisites

You have successfully logged in to the SAP BTP Cloud Foundry environment, targeted the specific organization and space where the agent will be deployed, and authenticated with Joule to deploy the custom capabilities.

- [Login to Cloud foundry](./1.1-Develop-Agent-And-Joule-Capabilities.md#login-to-cloud-foundry)

### Login to Joule CLI

> [!NOTE]  
> If you have already copied the BTP account subdomain and service bindings of SAP AI Core and saved them in your [Notes](../Notes.md), proceed with login. If not, follow the steps outlined below to retrieve the details and ensure you save them in [Notes](../Notes.md) for future reference.

1. Go to **BTP Cockpit → HOW-PA Joule Agent nnn → Overview**.
2. For the `BTP_ACCOUNT_SUBDOMAIN`, get the `SubDomain` from the `General` section.
3. Go to **Services → Instances and Subscriptions**.
4. Find and open the `das-<nnn>` instance. You can search for it by name or look for **SAP Digital Assistant** in the service column.
5. Go to **Service Bindings** and click **View** on the `das-<nnn>-key` binding to see the credentials.
6. For the `AUTHENTICATION_URL`, get the `uaa.url` value.
7. Copy the values for `uaa.clientid` for `CLIENT_ID`, and `uaa.clientsecret` for `CLIENT_SECRET`.
8. Open a Terminal (in VS Code or your system terminal).
9. Run the following command:

   **macOS / Linux (bash):**

   ```bash
   joule login --sso-passcode --no-app-tid --apiurl https://<BTP_ACCOUNT_SUBDOMAIN>.eu10.sapdas.cloud.sap -a '<AUTHENTICATION_URL>' -c 'CLIENT_ID' -s '<CLIENT_SECRET>'
   ```

   **Windows (PowerShell — use double quotes):**

   ```powershell
   joule login --sso-passcode --no-app-tid --apiurl "https://<BTP_ACCOUNT_SUBDOMAIN>.eu10.sapdas.cloud.sap" -a "<AUTHENTICATION_URL>" -c "CLIENT_ID" -s "<CLIENT_SECRET>"
   ```

   > **`--no-app-tid` flag:** Suppresses the application tenant ID prompt. Without this flag the CLI asks for an additional tenant ID that is not required in this setup.

You will receive a link to generate a passcode. Open the link in a browser and log in using your IAS tenant username and password. A passcode will be displayed after authentication — copy it and paste it back into the terminal.

> [!NOTE]
> If the login page redirects incorrectly or shows a "session already active" error, open the link in an **incognito / private browsing window** and log in there.

> [!IMPORTANT]
> `joule login` only works after the `das-<nnn>` instance with the `designer` plan is created in your subaccount and you have the required [roles](#assign-joule-user-roles) to develop custom capabilities.

## Deploy the Agent using Plugin

Give Claude Code the following prompt. Claude in turn loads the joule-a2a-agent skill (deploy-agent) and starts building the agent.

> [!IMPORTANT]
> Verify that you are targeting the correct Cloud Foundry organization and space using `cf target`, and ensure the appropriate Joule instance is selected using `joule status` to prevent configuration issues.

```text
Deploy the agents with Joule capabilities.
```

**What happens in the background:**

1. **Detect project type** — the plugin reads the `mta.yaml` and `package.json` files to confirm this is a CAP-based A2A agent, then checks the Joule tenant's A2A protocol version to ensure schema compatibility.
2. **Build the MTA archive** — runs `mbt build` to compile the TypeScript source and package the app with its service bindings into a deployable `.mtar` archive.
3. **Deploy to Cloud Foundry** — runs `cf deploy` with the `.mtar` archive. CF provisions the destination service instance, binds it to the app, and starts the `psm-joule-agent-srv` process.
4. **Verify the agent card** — once the app is running, it polls `/.well-known/agent.json` on the live URL to confirm the agent is reachable and responding correctly.
5. **Create the Joule destination** — creates the `PSM_JOULE_AGENT_A2A` HTTP destination in the Joule subaccount pointing to the deployed agent URL.
6. **Deploy Joule capabilities** — runs `joule deploy` with the capability YAML files so Joule can route user intents to the agent.

> [!IMPORTANT]
> The plugin handles deployment step by step. If a step fails (build error, CF staging failure, agent card returning 404, destination misconfiguration), it tries to fix and redeploy. In case if it stops and shows the error. Ask Claude Code to diagnose the root cause and retry. You don't need to manually inspect logs or re-run commands unless prompted.

**Verify that the application is running:**

```bash
cf apps
```

Expected output (truncated):

```
name                    requested state   processes   routes
psm-joule-agent-srv     started           web:1/1     <your-org>-<space>-psm-joule-agent-srv.cfapps.eu10-005.hana.ondemand.com
```

Copy the route of `psm-joule-agent-srv` — this is your `<AGENT-SERVICE-URL>`.

If you want to check logs, run the following:

```bash
# Most recent logs
cf logs psm-joule-agent-srv --recent

# Live tail (useful during a test)
cf logs psm-joule-agent-srv
```

Key log lines to look for are listed below:

| Log line                                          | Meaning                                                    |
|---------------------------------------------------|------------------------------------------------------------|
| `[MCP] Fetching destination 'PSM_CAP_APP'...`     | Agent is calling SAP BTP Destination Service for a fresh token |
| `[MCP] Got Bearer token from destination service` | Token fetched successfully                                 |
| `[MCP] Loaded N tools from PSM MCP server`        | MCP connection established                                 |
| `[TOOL] query: {...}`                             | MCP tool was called and returned data                      |
| `Task <id> completed`                             | Agent finished successfully                                |

## Test and Troubleshoot the Deployed Agent

To test the deployed agent, you must first create a destination in the subaccount. This destination serves as the connection point to the Poetry Slam Manager application using the MCP.

> [!NOTE]  
> If you have already copied the service bindings of Poetry Slam Manager application service broker and saved them in your [Notes](../Notes.md), proceed with creating the destination with the details. If not, follow the steps outlined below to retrieve the details and ensure you save them in [Notes](../Notes.md) for future reference.

1. Get the information of the Poetry Slam Manager Application Service Broker Key.
    1. Go to **BTP Cockpit → HOW-PA Consumer nnn Subaccount → Services → Instances & Subscriptions**.
    2. Click on `psm-sb-sub<nnn>-full` service instance.
    3. Under **Service Bindings**, click `psm-sb-sub<nnn>-full-key` to view its credentials.

2. Go to **BTP Cockpit → HOW-PA Joule Agent nnn Subaccount → Connectivity → Destinations**.

3. Create a new destination with the following field values:

   | Parameter Name              | Value                                                          |
   | :-------------------------- | :--------------------------------------------------------------|
   | **Name**                    | `PSM_CAP_APP`                                                  |
   | **Type**                    | `HTTP`                                                         |
   | **Description**             | Destination description. For example, `Poetry Slams Manager`.  |
   | **URL**                     | `endpoints.psm-servicebroker`                                  |
   | **Proxy Type**              | `Internet`                                                     |
   | **Authentication**          | `OAuth2ClientCredentials`                                      |
   | **Client Id**               | `uaa.clientid`                                                 |
   | **Client secret**           | `uaa.clientsecret`                                             |
   | **Token Service URL**       | `Get uaa.url and append /oauth/token`                          |
   | **Token Service URL Type**  | `Dedicated`                                                    |

> [!TIP]
> If any application functionality fails during testing, use Claude Code to diagnose the issue and trigger an automated redeployment.

- The agent card describes the agent's capabilities to Joule. Verify it is accessible:

    ```bash
    curl https://<AGENT-SERVICE-URL>/.well-known/agent.json | jq
    ```

- **List All Poetry Slams — `message/send` (A2A v0.3, direct agent call):**

    ```bash
    curl -X POST https://<AGENT-SERVICE-URL>/ -H "Content-Type: application/json" \
    -d '{
            "jsonrpc": "2.0",
            "id": "1",
            "method": "message/send",
            "params": {
              "message": {
                "role": "user",
                "parts": [{"kind": "text", "text": "Show me the list of poetry slams"}],
                "messageId": "m1",
                "contextId": "c1"
              }
            }
        }' | jq
    ```

    **PowerShell (Windows):**

    ```powershell
    $body = '{"jsonrpc":"2.0","id":"1","method":"message/send","params":{"message":{"kind":"message","messageId":"m1","role":"user","parts":[{"kind":"text","text":"Show me the list of poetry slams"}]}}}'
    Invoke-RestMethod -Uri "https://<AGENT-SERVICE-URL>/" -Method POST -ContentType "application/json" -Body $body | ConvertTo-Json -Depth 20
    ```

- **List All Poetry Slams — `tasks/send` (A2A v0.2, what Joule sends):**

    ```bash
    curl -X POST https://<AGENT-SERVICE-URL>/ -H "Content-Type: application/json" \
    -d '{
            "jsonrpc": "2.0",
            "id": "1",
            "method": "tasks/send",
            "params": {
              "id": "t1",
              "contextId": "c1",
              "message": {
                "role": "user",
                "parts": [{"type": "text", "text": "Show me the list of poetry slams"}],
                "messageId": "m1"
              }
            }
        }' | jq
    ```

> [!NOTE]
> If `jq` is not installed, omit `| jq` — the response still prints, just unformatted. On Windows, install from [jqlang.org](https://jqlang.org/download/) or use `Invoke-RestMethod` as shown above (it pretty-prints JSON automatically).
